## 简历正文

### Ragent｜企业知识问答与业务办理 Agent 平台

项目时间：【实际起止时间】

技术栈：Java 17、Spring Boot、AgentScope、PostgreSQL / pgvector、Redis / Redisson、MCP、Reactor、SSE、RocketMQ。

项目简介：面向企业知识问答与业务办理，主导 Ragent 平台建设，提供 Workflow 与 ReAct 两种执行模式。将知识检索、Skills 与 MCP 工具串联为多步骤任务，通过人工确认、会话状态恢复和分层记忆管理执行过程，支持连续追问与暂停后的恢复。

个人职责：

- 基于 AgentScope ReAct 统一接入知识检索与 MCP 工具，以 PostgreSQL 持久化会话状态；结合 Redis 运行位、跨节点取消与 SSE 收尾机制，支持多轮任务恢复和流式执行控制。
- 设计 Skills 按需加载与工具双重校验，随技能手册退出上下文收回关联工具；为 MCP 写操作及需确认工具接入 HITL，恢复时从服务端状态读取原始参数，约束未确认调用及参数篡改。
- 构建可配置的向量、关键词与图谱混合检索链路，以加权 RRF 融合多路排名，串联 Rerank 和证据相关性门控，并拆分召回、精排候选及最终上下文预算。
- 构建工具结果裁剪、会话摘要与跨会话事实记忆，保护近期消息及工具调用配对；采用事务外模型判定、短事务内版本号与处理水位双校验，防止过期抽取结果覆盖新事实。
- 为 RAG 模型调用实现档位路由、候选降级与三态熔断，在流式首包探测成功后提交缓冲，隔离首包提交前失败候选的输出；首包等待中断时释放半开名额，避免取消阻塞后续探测。

## 对模板的调整

| 个人职责与账号归属 | 根据本轮“另一账号全程主导”的用户说明，以主导项目及设计实现表述；更正此前研习定位 |
| “企业级”与真实商城运营场景 | 使用企业知识问答与业务工具调用作为能力背景；商城代码和初始化数据只能证明示例业务存在 |
| “三路混合检索” | 描述可配置检索链路；当前向量开启，关键词、图谱和联网通道关闭 |
| RAGAS、20+ 指标、A/B Diff、Faithfulness +10.3%、Answer Relevancy +8.0% | 当前仓库未找到对应评测实现与结果记录，移出简历；检索证据接口不能证明端到端回答质量评测 |
| “有效控制 Token 成本” | 保留压缩机制；当前预算按字符估算，没有本人 Token 成本对照实验 |
| “防止重复执行” | 仅描述运行位互斥与状态控制；外部 MCP 业务副作用需要单独的幂等保证 |
| 全链路 Langfuse 追踪 | 追踪接入代码存在，当前 `agent.trace.enabled=false`；不写成已启用并完成运行验证 |
| 模型降级适用于整个 Agent | 限定为 RAG / infra-ai 模型调用；主 Agent 使用独立单模型配置 |
